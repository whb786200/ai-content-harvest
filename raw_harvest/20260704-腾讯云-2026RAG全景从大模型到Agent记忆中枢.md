# 2026 RAG全景：从大模型基座到Agent记忆中枢

## RAG核心思路
在让大模型作答前，先去外部知识库找相关信息，连同问题一起交给大模型。
**三步**: Retrieval检索 → Augmentation增强 → Generation生成

- **解决**: 知识时效性、幻觉抑制、私有知识接入、可追溯性、成本可控
- **未解决**: 复杂推理、极致实时性、跨文档关联推理

## RAG五代演进

| 代际 | 时期 | 核心 |
|------|------|------|
| 第一代 | 2020 | Facebook首提，端到端可训练，学术圈 |
| 第二代 | 2022-23 | Prompt Engineering把检索结果塞入上下文，LangChain/LlamaIndex |
| 第三代 | 2023-24 | Advanced RAG: Pre/During/Post-Retrieval三环节优化 |
| 第四代 | 2024 | Modular RAG: 模块化动态组合，从流水线到平台 |
| 第五代 | 2025+ | Agentic RAG: LLM自主决策检索，ReAct框架 |

## 架构设计要点

### 数据入库流水线
原始文档 → 文档解析 → 文本清洗 → 文本切分 → 向量化 → 写入向量库
- 元数据至关重要: chunk_id, source, page, chapter, created_at, doc_type
- 增量更新策略: 新增/更新/删除

### 查询增强四手段
1. **查询改写**: 去口语化、补全指代
2. **多查询生成**: 一问扩展3-5个子查询
3. **问题分解**: 复杂问题拆子问题
4. **HyDE**: LLM生成假设答案，用答案去检索

### 混合检索
- 向量检索(语义) + BM25(关键词) → RRF融合排序
- 初始权重: 向量:BM25 = 0.7:0.3
- RRF: score(doc) = Σ 1/(k + rank + 1), k=60

### 重排序
- Bi-Encoder大范围快速召回 → Cross-Encoder精确重排
- 中文首选: BGE-Reranker

## Agent记忆中枢

### Agentic RAG
LLM自主判断: 召回是否足够、是否多轮检索、选择数据源、评估答案可靠性
基于ReAct: Think → Act → Observation → Think → Answer

### Self-RAG & CRAG
- Self-RAG: 自主判断是否需要检索、内容是否相关
- CRAG: 召回不足时自动触发Web Search补充

### 长上下文 vs RAG
- 长上下文: 无需检索，但成本极高、大海捞针
- RAG: 超大规模知识库、强可溯源、频繁更新、成本可控
- **趋势**: RAG精拣 + 长上下文LM理解

## GraphRAG
- 解决传统RAG的Chunk间无显式关系问题
- 抽取实体与关系 → 构建知识图谱 → 图遍历多跳查询
- 优势: 关联推理、全局摘要、可解释性
- 代价: 构建维护成本高、延迟更高

## 落地选型指南

### 文档解析
PyMuPDF(轻量) / Docling(复杂排版) / Unstructured(多格式) / MinerU(中文)

### Chunking策略
- 固定大小(300Token, 50重叠) — 入门
- 语义切分 — 语义敏感
- 递归结构切分 — 通用
- 父子Chunk — 进阶推荐(小检索128, 大返回512-1024)

### Embedding选型
- 中文: BGE-M3(支持密集+稀疏+多向量) / BGE-large-zh
- API: text-embedding-3-small(性价比)
- 本地: BGE系列(数据保密)

### 向量数据库
- 快速验证: Chroma/FAISS
- 已有PG: pgvector
- 中小企业: Qdrant
- 大规模企业: Milvus
- 零运维: Pinecone

### LLM选型
- 最强: GPT-4o / Claude 3.5 Sonnet
- 平衡: GPT-4o-mini / Gemini Flash
- 中文: Qwen2.5-72B / DeepSeek-V3
- 本地: Qwen2.5-32B / Llama 3.3 70B

### RAG框架
- 代码: LangChain(生态全) / LlamaIndex(专注RAG) / Haystack(企业级)
- 低代码: Dify(国内流行) / FastGPT(知识库专项) / Coze(Agent集成)

## 三阶段落地路径

| 阶段 | 周期 | 目标 | 技术栈 |
|------|------|------|--------|
| 快速验证 | 1-2周 | 跑通流程 | PyMuPDF+Chroma+BGE-M3+GPT-4o-mini+LlamaIndex |
| 效果优化 | 2-4周 | 70%→85%+ | 评估集+查询改写+混合检索+重排序+Prompt优化 |
| 生产化 | 4-8周 | 真实用户 | 生产向量库+全链路日志+数据飞轮+监控 |

## 避坑清单
- 不过早优化: 先跑通基础RAG再玩GraphRAG
- 不忽视数据质量: 垃圾进垃圾出
- 不一刀切Chunk: 不同文档不同参数
- 不只靠向量: 精确词必须配合BM25
- 不忘权限控制: 按角色过滤
- 不只看答案: 要看召回质量
- 不过度依赖框架: 要看中间日志

## 核心洞察
> RAG是一种思路，不是一项单一技术。本质是：在需要知识时动态检索，而不是把所有知识固化在模型里。
> RAG 80%的问题是数据问题，不是技术问题。
> 技术选型核心原则：匹配场景，简单优先。
