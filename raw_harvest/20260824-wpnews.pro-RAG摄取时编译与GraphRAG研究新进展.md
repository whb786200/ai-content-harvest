# Ingest-Time Compilation Takes On Query-Time RAG, and Agentic Retrieval Meets Its Limits

2026/8/17–24 RAG 与 GraphRAG 进展汇总（arXiv 新论文 + Hugging Face Daily Papers + 跟踪博客）。

## 🔥 Highlights
- **RAG Deserves an Index: Why Ingest-Time Compilation Beats Query-Time Interpretation** — 一次预编译 claim，停止每次查询重推含义。
- **LineageRAG** — 把 GraphRAG 证据锚定到逐字源 span，而非凭感觉。
- **When Failures Propagate: Causal Failure Attribution in Agentic RAG** — 诊断在 hop 1 后崩为 0。
- **Temporal Validity on Real Software Histories** — RAG 超 1/3 时间提供过时事实。
- **Secure GraphRAG** — Microsoft Copilot Studio 接 Neo4j + 每用户 Okta SSO 企业级 ACL。

## arXiv（cs.CL / cs.AI）

### RAG Deserves an Index: Why Ingest-Time Compilation Beats Query-Time Interpretation (2026-08-21)
主张"摄取时语义编译"：索引时预计算原子化、带溯源校验的 claim，而非每次查询从原始 chunk 重推含义。
- 编译 claim 正确率 **85.2%**（~2.2k tokens） vs chunk RAG **72.5%**（16.3k tokens）。
- 实践价值：当管线把上下文预算反复花在重解相同段落时，这是具体架构替代方案。

### Cost Scales with Change, Not Corpus Size: Incrementally Maintaining an Evolving Semantic Substrate (2026-08-17)
上述论文的工程伴侣：语义索引的增量低秩（SVD）更新比全量重建**每次更新便宜 33.7 倍**，且精度追平到浮点级。回答了"重索引会不会坑死更新"的异议。

### LineageRAG: Harnessing GraphRAG by Constructing Evidence Lineages with Source Grounding (2026-08-17)
每个查询建显式"证据谱系"，把图遍历每一跳锚定到逐字源 span（而非留隐式证据链）。
- 在 HotpotQA / 2WikiMultiHopQA / MuSiQue 上超越领先 GraphRAG 基线：**R@5 +3.51 / EM +5.96 / F1 +5.22**。
- 适用：GraphRAG 答案准但无法审计时。

### When Is Complex Chunking Worth It? A Multi-Objective Evaluation of Chunking Methods at Scale (2026-08-17)
跨 2 语料、3 嵌入模型、多语料规模评估 8 种切分策略的检索质量与运维成本（吞吐/延迟/内存）。
- 结论：计入成本后，复杂切分很少持续划算 → 反对过度工程化 chunker 的弹药。

### When Failures Propagate: Causal Failure Attribution in Agentic RAG (2026-08-20)
提出 **AgenticRAG-FP**：在特定 hop 注入认证故障，检查轨迹改变后事后诊断能否仍发现它。
- 基于覆盖的诊断在 **hop 1 之外崩为 0.00 准确率** → 对基于 agentic RAG 的"解释 agent 为何失败"工具是硬警告。

### VisDocAgentBench: Benchmarking Agents for Visually Rich Document Retrieval (2026-08-18)
强静态检索器在视觉丰富文档直接查询上 R@1 **97.5%**，但两跳（multi-hop）仅 **2.5%**；agentic 搜索挽回大部分损失。量化了 agentic 检索成本花在哪、浪费在哪。

### Temporal Validity on Real Software Histories: Eliminating Stale-Fact Errors in Code-Assistant Memory (2026-08-21)
130 个真实 GitHub issue 状态转移验证：标准 RAG 无时间模型，即使带 LLM reranker，仍 **36–38%** 时间提供被取代事实。确定性 supersession-memory 系统（MemStrata）在可比延迟下降到 ~0。

### Weighted Memory Tree: Remembering What Matters for Long-Horizon LLM Agents (2026-08-21)
分层记忆（tasks/subtasks/actions）+ 每记忆保留分与衰减，替代扁平增长 transcript。
- GAIA-Text 上比线性记忆 **+9.97 点**准确率，同时砍 **32.8%** prompt tokens → 长运行 agent 实用剪枝技术。

## Hugging Face Daily Papers
- **Graph Engineering in the Era of LLM Agents** (2026-08-21)：立场文，提"图工程"作为 prompt/context/harness 工程的继任者——显式演进图结构协调多 agent 系统的任务/agent/系统状态；图本身成为整个 agent 系统的协调层。
- **EviRank** (2026-08-21)：重排重定义为约束满足——把查询解析为 typed 标准（required/forbidden/ignorable）跨 6 语义槽，确定性 rubric + 证据支撑 listwise 比较；5 多模态基准 SOTA，蒸馏学生保留 90%+ 教师质量。
- **MemTrapBench** (2026-08-20)：即使忠实检索的相关记忆也会扭曲推理（推理固着/信念扭曲）；基准中每个记忆策略都不如无记忆基线，最佳方法仍亏 >10%；提出推理时指令修复（AdaptiveMem）。

## Neo4j blog
- **Secure GraphRAG: Wiring Microsoft Copilot Studio to Neo4j with per-user Okta SSO** (2026-08-20)：经 Neo4j MCP server on Cloud Run 把 Copilot Studio 接 Neo4j 图，转发每用户 Okta token 使图查询尊重每用户权限而非共享服务账号 → 解决企业 agentic GraphRAG 的"confused deputy"问题。

## Through-line（主线）
最强主线：检索从"查询时问题"转向"摄取时 + 溯源问题"——预编译语义索引、锚定逐字 span 的证据谱系、Neo4j 每用户访问接线，都把工作与责任前移而非指望查询时检索器答对。
第二主线：一组清醒基准回推假设——agentic 检索仅在真正多跳查询上赚回成本；更多检索记忆反而伤推理；普通 RAG 无时间概念、超 1/3 时间自信返回被取代事实。
结论：把"检索可用"当作需逐失败模式验证的声明，而非免费获得的属性。
