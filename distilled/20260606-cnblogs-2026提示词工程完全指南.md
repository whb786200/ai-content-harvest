# 2026提示词工程CREATE框架

> 来源：cnblogs.com · 2026提示词工程完全指南

## 2026年三个根本变化

1. **上下文窗口爆炸**：128K → 100万token（Claude Opus 4.7支持200万）
2. **推理能力跃升**：减少逐步指令，多定义目标，信任模型自主判断
3. **多模态成为标配**：图像理解/代码执行/工具调用融合在同一Prompt

## CREATE框架（2026升级版）

| 要素 | 说明 | 2026新变化 |
|------|------|-----------|
| C - Context | 告诉AI"你是谁" | 新增：明确"能力边界" |
| R - Request | 清晰的任务指令 | 新增：定义"成功标准"而非步骤 |
| E - Examples | 1-3个输入输出示例 | 新增：多模态示例 |
| A - Adjustments | 格式/字数/禁止事项 | 新增：输出验证机制 |
| T - Tone/Test | 输出风格语调 | 新增：思考过程展示程度 |

## 通用实战模板

```
【角色】你是一位拥有10年经验的[专业角色]
【边界】不确定时标注"需要人工确认"
【任务】请完成[具体任务]
【成功标准】完成的标志是：[可验证标准]
【输出格式】严格按格式输出
【验证要求】输出前自我检查：[检查清单]
```

## 十大进阶技巧

1. 指令前置+分隔符 — 指令放开头，内容用"""隔离
2. 具体到"令人发指" — 格式/长度/风格/受众全定义
3. Show, don't tell — Few-shot示例比描述有效
4. 增强型思维链 — 结构化5步思考框架
5. 模型专属优化 — Qwen/GPT/Claude各有专属参数
6. 长上下文黄金区域 — 开头5%放指令，结尾5%放参考
7. 输出格式契约 — 结构化格式约束（JSON/Markdown表格）
8. 多轮对话状态管理 — 短期记忆锚点+进度看板
9. 反馈闭环设计 — 先方案后实现，分步确认
10. 系统提示词隔离 — 建立"人格隔离区"保持风格一致

> OpenAI官方: "Trust the model's judgment. Define success, not process."

## 常见错误避坑

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| 一次性扔太长对话历史 | 模型迷失方向 | 每3-5轮总结上下文 |
| 用模糊词 | 模型无法理解标准 | 用可验证标准描述 |
| 忽略输出格式约束 | 每次手动整理 | 第一次就要求结构化输出 |
| 不验证AI输出 | 幻觉进入生产 | 要求附带置信度评分 |
