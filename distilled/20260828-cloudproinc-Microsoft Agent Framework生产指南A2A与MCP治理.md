## 核心主题

面向把AI agent推向生产的企业指南。Microsoft Agent Framework（.NET 1.19.0/Python 1.15.0）近期改进聚焦运维细节而非聊天花活：A2A成为实用服务边界、MCP引入Tasks扩展处理长运行操作、治理进入agent运行时（中间件/检查点）、持久化与恢复成董事会级议题。核心判断：真正的生产里程碑是**控制**——A2A/MCP/长运行agent更有用，也更能深入业务运营，抬高了弱身份/不清所有权/弱监控的代价。

## 方法论框架

### A2A vs MCP使用决策

| 维度 | 用A2A | 用MCP |
|------|-------|-------|
| 场景 | 跨系统/团队/语言/组织间真实边界 | 工具/数据受控访问 |
| 何时不用 | 两agent同应用同团队→直接内部workflow更简单更快更便宜 | — |
| 新能力 | 流式artifact更新（agent在另一agent仍工作时可靠接收部分输出） | Tasks扩展处理数分至数时操作 |
| 破坏性变更 | — | .NET 1.19.0长运行MCP迁移到新Tasks模型 |

### MCP Tasks扩展（长运行操作）

| 维度 | 旧模式 | Tasks扩展 |
|------|--------|----------|
| 连接 | 长连接赌不超时 | 建可查/可更新/可恢复的长久任务 |
| 适用 | — | 文档分析/批报/审批流/安全调查 |
| 风险 | — | 长任务在用户离开后仍消耗资金/访问系统 |
| 必须设计 | — | 身份/时限/成本限额/取消控制 |

### 治理进入运行时（中间件/检查点）

```
Agent: Supplier Invoice Review
Can read: 发票邮箱与采购单
Can propose: 不匹配标记与编码建议
Needs approval: 银行信息变更与付款释放
Cannot access: 薪酬或客户身份记录
Must log: 每次工具调用、A2A交接、审批
Stop conditions: 成本限额、超时或策略失败
```

| 控制层 | 能力 | 状态 |
|--------|------|------|
| Middleware（检查点） | 校验输入/拦截工具/请求人审/强制花费限额/记审计事件 | 已支持 |
| Agent-hooks契约 | 跨模型调用/工具使用/最终输出应用控制 | 实验方向 |
| 可问责性 | 出事时可定哪个agent行动/用谁身份/访问何信息/何策略允许 | 业务结果 |

### 持久化与恢复

| 维度 | 能力 | 新风险 |
|------|------|--------|
| 会话持久化 | 状态可存Azure Blob Storage | 存储状态含客户详情/内部文档/商业敏感推理史 |
| Hosted agent恢复 | 基础设施故障后恢复工作而不重来 | 新数据管理责任（保留期/存储地/可取回者） |
| 防重复 | 防重复业务事务 | — |

### 技术负责人六步行动

1. 盘点每个agent与MCP连接（owner/用途/数据访问/模型/托管地/业务影响）
2. 锁定并测试框架版本（协议与依赖快速变化，勿自动生产升级）
3. 区分A2A与MCP用例（agent间通信vs工具/数据受控访问）
4. 测试失败与恢复（超时/重复消息/权限撤销/部分结果/基础设施重启）
5. 加可执行控制（受限身份/中间件/人审/预算/明确停止条件）
6. 监控业务结果（处理时长/错误率/审批延迟/AI消耗/事件）而非数对话数

## 关键洞察

1. **真正的生产里程碑是控制而非能力**：A2A/MCP/长运行agent更有用，也更能深入业务运营——抬高了弱身份/不清所有权/弱监控的代价
2. **A2A何时不该用**：两agent同应用同团队时直接内部workflow更简单更快更便宜——A2A只在跨越真实系统/团队/语言/组织边界时使用
3. **MCP Tasks扩展是长运行操作革命**：从"长连接赌不超时"到"建可查/可更新/可恢复的长久任务"——但身份/时限/成本限额/取消控制必须进设计
4. **书面AI政策无法阻止agent凌晨2点未授权工具调用**：生产治理需在agent真正决策与行动的运行时内加控制（中间件/检查点）
5. **持久化与恢复成董事会级议题**：agent存储状态可能含客户详情/商业敏感推理史——新数据管理责任（保留期/存储地/可取回者）
6. **监控业务结果而非数对话数**：处理时长/错误率/审批延迟/AI消耗/事件
