# 清华大学智能体安全研究报告2026：Agent安全从模型层转向运行时系统安全

> 来源：搜狐/清华大学清新研究团队 · 2026-06-09 · https://www.sohu.com/a/1034036233_468661

---

## 核心主题

智能体（Agent）安全已从模型层安全演进为**运行时系统安全**。Agent不是聊天机器人，而是"带权限的运行时系统"，其安全边界远大于普通对话模型。企业核心竞争力在于**安全控制平面**的构建，而非依赖单个大模型的安全能力。报告系统提出七层安全控制框架、十大高频风险清单、五级成熟度模型和180天落地路线图。

## 方法论框架

### Agent Safety 公式

```
Agent Safety = 身份 + 策略 + 工具 + 日志
```

### 七层安全控制框架

| 层级 | 控制对象 | 核心措施 |
|------|----------|----------|
| 1. 身份层 | Agent身份 | 独立身份链路，禁止长期持有人类凭证 |
| 2. 权限层 | 操作权限 | 最小权限+短期可撤销，高风险动作强制审批 |
| 3. 工具层 | 工具调用 | 风险标签+调用规则，调用前后策略校验 |
| 4. 上下文层 | 输入数据 | 隔离不可信数据，防范上下文投毒 |
| 5. 记忆层 | 持久状态 | 读写管控，版本回溯+删除回滚 |
| 6. 沙箱层 | 执行环境 | 代码/文件/命令强制隔离，限制网络与资源 |
| 7. 审计&人工层 | 全链路 | 全量操作日志(Action Ledger)，高风险人工审批门 |

### 十大高频风险分类

| 类型 | 代表风险 |
|------|----------|
| 高频类 | 目标劫持、提示词注入、工具滥用、身份/权限滥用 |
| 持续性 | 记忆污染、上下文投毒（跨任务延续） |
| 扩散类 | 沙箱逃逸、供应链污染、多Agent级联失败 |
| 衍生类 | 数据泄露、意外代码执行、审计缺失 |

### 成熟度五级模型

```
L1 只读 → L2 受限工具 → L3 半自动 → L4 闭环自治 → L5 高保证自治
                                          ↑
                               建议企业优先落地 L2-L3
```

### 180天落地路线图

```
0-30天   → 资产盘点：梳理所有Agent与高权限工具
30-60天  → 搭建权限/日志/审批基线，统一安全策略
60-90天  → 低风险场景试点，红队渗透测试
90-180天 → 平台化：注册中心+策略引擎+沙箱
1年目标  → 统一安全控制平面，核心Agent全面接入
```

## 工具链

| 类别 | 组件 | 说明 |
|------|------|------|
| 控制平面 | Agent/工具注册中心 | 全量登记，风险等级标注 |
| 策略引擎 | 身份/权限/数据校验 | 每次工具调用前校验 |
| 基础安全 | 上下文防火墙+DLP+沙箱 | 数据脱敏、隔离执行 |
| 审计应急 | 全链路日志+熔断+回滚 | Action Ledger可追溯 |
| 协议风险 | MCP协议 | 简化工具接入但扩大攻击面，需纳入安全控制平面 |

## 关键洞察

1. **Agent ≠ 聊天机器人**：Agent是带权限的运行时系统，仅靠提示词无法保障工具调用安全——这是整个报告的基石判断
2. **企业核心竞争力 = 安全控制平面**：不是拥有最强的单个大模型，而是拥有统一的安全管控体系
3. **MCP协议是双刃剑**：简化工具接入的同时同步扩大攻击面，必须将MCP工具纳入安全控制平面管理
4. **落地优先级铁律**：先资产清单→权限管控→全量日志，再放开工具能力——不能先跑后系鞋带
5. **多Agent级联失败**：扩散类风险中最危险的一种，需提前评估七层框架设计

## 适用场景

- **代建项目AI应用**：Agent用于安全巡检、合规审查，必须配置安全控制平面
- **多Agent协作系统**：级联失败风险需提前评估，参考七层框架设计
- **MCP工具接入**：每个MCP工具需纳入注册中心+策略引擎管理
- **企业AI安全治理**：按180天路线图分阶段落地，L2-L3起步
